# 上架 Chrome 線上應用程式商店

這份文件把上架要填的欄位都寫好了，多數可以直接複製貼上。
素材放在 `store-assets/`，套件用 `npm run build` 產生。

## 一、前置作業

1. 到 [Chrome 開發人員資訊主頁](https://chrome.google.com/webstore/devconsole) 用 Google 帳號登入。
2. 繳交**一次性 5 美元**的開發者註冊費（不是訂閱制，繳一次即可）。
3. 填寫開發者聯絡 email 並完成驗證——**這是必要步驟**，沒驗證不能發布。

## 二、產生上傳用的套件

```bash
npm test          # 先確認測試通過
npm run build     # 產出 dist/social-media-alert-<版本>.zip
```

上傳的是 zip 檔本身，不需要解壓縮。

```
在 Facebook、Threads 上遇到你清單中標記過的粉專時跳出提醒。清單自己掌握，完全在本機運作，不蒐集任何資料。
```

### 詳細說明

```
「社群媒體警示」是一個本機運作的查核輔助工具。當你在 Facebook 或 Threads 瀏覽時，
如果遇到警示清單中的粉專或帳號，它會在頁面頂端顯示提醒，並在動態牆的貼文上加註標記，
讓你在閱讀內容前先知道「這個帳號之前被標記過」。

■ 主要功能

・頁面警示橫幅：進入被標記帳號的頁面時跳出提醒，顯示標記等級、原因與來源。
・動態牆標記：被標記帳號的貼文會加上警示條與外框，連結會加上底線與符號。
・一鍵加入清單：在任何粉專頁點開工具列圖示，填寫原因與等級即可加入。
・四種標記等級：高風險、需留意、提醒，以及「已澄清」。
・「已澄清」是反向標記：用來標示名稱相似但查證後無關的粉專，顯示綠色提示而非警示，
　避免同名帳號被誤認。
・清單管理：搜尋、依平台與等級篩選、刪除、匯入／匯出 JSON。
・訂閱清單：可填入一個回傳 JSON 的網址，定期同步他人維護的清單。

■ 隱私

・所有清單與設定都存在你的瀏覽器本機，不會上傳到任何伺服器。
・沒有後端伺服器，開發者看不到你的清單，也看不到你瀏覽了什麼。
・不使用 Cookie、不做追蹤、不使用任何分析服務。
・只在 facebook.com、threads.net、threads.com 上執行，讀不到其他網站的網址或內容。
・唯一的對外連線是你自己填寫的訂閱清單網址；沒填就完全不連外。

隱私權政策：https://mark780825.github.io/social_media_alert/privacy.html

■ 關於內建清單

安裝後會載入一份內建清單，整理自公開報導中被具名的粉專，每一筆都附上依據來源。
這份清單是**參考資料，不是事實認定**，你可以隨時修改或整份刪除，也可以完全換成自己的清單。
清單的收錄標準、查證流程與申訴管道都公開在專案網站上。

■ 開源

原始碼完全公開，任何人都可以檢查它實際做了什麼：
https://github.com/mark780825/social_media_alert

採用 MIT 授權。
```

## 五、隱私權分頁（Privacy practices）

這是最容易被退件的地方，每一欄都要填。

### 單一用途說明

```
在 Facebook 與 Threads 上，比對使用者自己維護的帳號清單，並在遇到清單中的帳號時顯示提醒。
```

### 權限理由

| 權限 | 填寫內容 |
| --- | --- |
| `storage` | 在使用者的瀏覽器本機儲存警示清單與偏好設定。不會傳送到任何伺服器。 |
| `alarms` | 當使用者自行啟用「訂閱清單自動更新」時，用來排定定期更新的時間。未啟用時不會使用。 |
| 主機權限 | 擴充功能需要在 facebook.com、threads.net、threads.com 上讀取目前頁面的帳號代號與粉專名稱，才能比對清單並顯示警示橫幅與貼文標記。比對完全在本機進行，不會傳送任何頁面內容。 |

### 遠端程式碼

選 **不使用遠端程式碼（No, I am not using remote code）**。

訂閱清單下載的是 JSON 格式的**資料**，不是可執行的程式碼；所有程式碼都包含在套件內。
如果審查員追問，用這段說明。

### 資料使用聲明

所有「是否蒐集」的項目**全部不勾選**，包括：個人識別資訊、健康資訊、財務與付款資訊、
身分驗證資訊、個人通訊內容、位置、網頁記錄、使用者活動、網站內容。

底下三項聲明則**全部勾選**：

- 不會將使用者資料販售給第三方，與核准用途無關者除外
- 不會將使用者資料用於或轉移至與項目單一用途無關的用途
- 不會將使用者資料用於或轉移至判定信用度或貸款用途

## 六、發布設定

**顯示設定**建議先選 **未列出（Unlisted）**：

- 只有拿到連結的人能安裝，不會出現在商店搜尋結果。
- 適合先給小範圍的人試用，確認沒問題再改成公開。
- 之後隨時可以在主控台改成「公開」，不必重新審查。

**發布地區**可選全部，或只選台灣。

## 七、審查會看什麼

首次審查通常需要幾天，這類工具可能被多看幾眼。以下是最可能被追問的點與回應方向：

**Q：為什麼需要在 Facebook／Threads 上執行？**
擴充功能的核心功能就是在這兩個網站上比對頁面帳號並顯示提醒，沒有主機權限就無法運作。
權限只涵蓋這三個網域，不含任何其他網站。

**Q：內建清單是否構成對特定對象的指控？**
清單是使用者可完全修改與刪除的參考資料，每筆都附公開資料來源，並提供公開的申訴管道。
擴充功能本身不對任何帳號做出判斷，只是顯示使用者自己清單中的標記。

**Q：是否蒐集使用者資料？**
完全沒有。沒有後端伺服器，沒有分析工具，資料只存在使用者本機的 chrome.storage.local。

若被退件，退件信會寫明違反哪一條政策，依該條修正後重新送審即可，不需要重新繳費。

## 八、發布後更新版本

1. 修改 `manifest.json` 的 `version`（例如 `0.1.0` → `0.1.1`），版本號只能往上加。
2. `npm run build` 重新打包。
3. 在主控台的「套件」分頁上傳新的 zip，送出審查。

更新內建清單時記得一併更新版本號，否則使用者不會收到新清單；
另一個作法是請使用者使用「訂閱清單」功能，這樣清單更新不必經過商店審查。
